# Changelog

## Unreleased

- New package. `eve-pdpa-mcp`, an MCP server over stdio with two tools: `pdpa_scan`, which reports what Thai personal data a text holds and where (type, start, end, confidence, the policy's action) and never the values or the text, and `pdpa_redact`, which returns the text protected as the policy says. Both take an optional `context`, the message before, read for cue words only. Without `--policy` every type is redacted; a policy that tokenises is refused at start, as there is no tool to resolve a token, and one that hashes needs `PDPA_HMAC_KEY`. A blocked text is a tool error naming the types, with no text. Audit events go to stderr, or to a file with `--audit`: a new file is readable by its owner only, a file that cannot be written stops the start (exit 2), and a write that fails later is reported on stderr by event type and error code. `text` and `context` take up to 20,000 characters each, which keeps the slowest known input under a second. Any error inside the guard is answered with a fixed message, so no part of the text can travel in it. `createPdpaServer` is exported for a host with its own transport. Built on the official MCP SDK (`@modelcontextprotocol/server` 2); Node 20 or later.
